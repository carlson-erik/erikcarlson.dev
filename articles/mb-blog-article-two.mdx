This post picks up where [part 1](/writing/mb-blog-article-one) left off. Part 1 covers running text. This part covers the elements that are hardest to fit into a column of text, like code blocks, tables, and images, along with the rules MDX adds for HTML and special characters. Where there's something specific to look for, the section says what it should look like.

Check it in both themes, and in a desktop window, a tablet-sized one, and a phone. Some elements here are wider than a phone's screen on purpose. Each one should scroll or shrink on its own, and the page itself should never scroll sideways.

The release date is a test too. A date like `1994-01-01` is read as midnight UTC, so anywhere west of UTC, a time zone bug would show this post as released on December 31, 1993, and file it under 1993 on the Writing page. It should read January 1, 1994 everywhere. Both parts share that date, so the Writing page sorts them by title, which lists part 1 first.

## Code blocks

Fence code with three backticks, and name its language after the opening fence so syntax highlighting can color it. Every block should keep its indentation and blank lines exactly as written.

TypeScript, from this site's own types:

```ts
/** The front matter every file in /articles must have. */
export interface ArticleFrontMatter {
  title: string;
  /** Release date, "YYYY-MM-DD". */
  date: string;
  /** One or two sentences. Shown under the title on /writing. */
  description: string;
  /** Whole minutes. Shown as "8 minute read". */
  minutesToRead: number;
}
```

```tsx

  return <span className="read-length">{`${minutes} minute read`}</span>;
}
```

## Tables

The row of dashes under the header sets each column's alignment: `:---` for left, `---:` for right, and `:---:` for center. Right-align numbers so their digits line up:

| Post length    | Words | Minutes to read |
| :------------- | ----: | :-------------: |
| A short note   |   200 |        1        |
| A typical post | 1,500 |        7        |
| A deep dive    | 4,500 |       20        |

Cells can hold formatting, links, and code. A pipe inside a cell needs a backslash in front of it, even inside code, and `<br />` starts a new line within a cell. Cells can also be empty:

## HTML inside a post

Posts are `.mdx` files, so a few HTML tags can fill gaps that Markdown leaves, like the keyboard keys in [part 1](/writing/mb-blog-article-one#emphasis-and-inline-code) and the figure above. MDX reads them as JSX, which is stricter than HTML: close every tag, including empty ones like `<br />` and `<img />`, and quote every attribute value. Leave out `style` and `class`. Styling belongs to the site, and a `style` written as text stops an MDX page from rendering.

A `<details>` element hides a tangent until the reader opens it. Leave a blank line after the summary and before the closing tag, so the Markdown inside still works:

<details>
  <summary>Why can't a post use HTML comments?</summary>

  In MDX, `<` starts a tag, and `<!--` isn't one, so the file won't compile. MDX has its own comment syntax, `{/* like this */}`, but that shows up as text anywhere the post is read as plain Markdown. A link reference that nothing uses works everywhere:

  ```mdx
  [//]: # "A note to myself. It never appears on the page."
  ```

  There's a real one at the end of [Special characters & escapes](#special-characters--escapes).

</details>

## Special characters & escapes

Type punctuation as the characters themselves: “curly quotes,” ‘single quotes,’ an apostrophe in it’s, an em dash — for a break in thought, an en dash for ranges like 2025–2026, an ellipsis…, and symbols like ×, →, ≠, and °. Other languages keep their accents and scripts: café, naïve, Zürich, 日本語, Ελληνικά. Emoji should sit on the line without pushing the lines apart: ✅ ✍️ 🚀

HTML entities work too: &copy; &rarr; &mdash; &amp;. A non-breaking space, `&nbsp;`, keeps a number and its unit on the same line, as in 10&nbsp;km.

A backslash shows the next character as typed instead of letting it format the text: \*not italic\*, \_not italic\_, \[not a link\](/writing), and \`not code\`. At the start of a line, it stops a `#` from making a heading and a number from starting a list:

\# This line starts with a hash but isn't a heading.

1986\. This line starts with a year but isn't a list.

MDX adds two more characters to escape in text. Curly braces run JavaScript, so write \{ and \} to show them. A `<` followed by a letter or a digit starts a tag, so write \<div\> or `&lt;div&gt;`. Inside code, nothing needs escaping: `{ "a": 1 } < 2`.

[//]: # "A comment. If this text appears anywhere on the page, comments are broken."
